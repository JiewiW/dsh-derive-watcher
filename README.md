# dsh-derive-watcher

三层治理里，前两个插件管一次生成内和跨步骤的重复，这个插件看的是整轮会话有没有真的往前走。它把每个回合记成一本账：哪些是新发现、哪些是决定、哪些是走过又否掉的死路；死路全量留着，折叠归档时也不会丢。真要拦工具或步骤就交给姊妹插件；会话被步数上限或错误打断、没留下结论时，也能识别出来并决定是否续跑。「什么算停滞、什么算有进展」的口径和逐版装机实测由我定，代码借助 AI 协作完成；真实语义停滞下的端到端实跑还缺一次，这条列在待办里。

DeepSeek Harness（DSH）插件，观察 agent 会话的语义进展：把每个助手回合沉淀成一本「语义旅程账本」，模型语义停滞时分级告警，并向上层治理请求干预。

默认会主动把未完成目标、里程碑和最近的死胡同塞回上下文，也会在停滞升级时请求上层治理拒读某类工具或软切；真正拦截仍由姊妹插件 step-governor 动手，它不在线时本插件自动放行（fail-open），不会因为治理联动失败卡住任务。

## 三层治理中的位置

| 层 | 插件 | 职责 |
| --- | --- | --- |
| L1 | [dsh-cot-anchor](https://github.com/JiewiW/dsh-cot-anchor) | 单次生成内的软切与打转判定 |
| L2 | [dsh-step-governor](https://github.com/JiewiW/dsh-step-governor) | 跨步骤治理：工具限流、步骤拒绝 |
| L3 | 本插件 | 会话语义旅程账本、新颖性判定、里程碑折叠、上下文注入、三级停滞响应 |

## 它具体做什么

语义旅程账本：把每个助手消息总结成结构化条目（新发现、决定、死路、假设、计划、事实），JSONL 与 Markdown 双镜像落盘。每条写入都做长度守恒校验并回读验证，校验失败只丢弃这一条、发事件告警，不会让账本静默损坏。水位线记录每会话最后处理到的消息，进程重启后自动幂等补扫，不永久漏账。思考块与正式正文分开观察、走独立账本，思考内容不混进正式结论。

小结与折叠：条目由小模型异步总结产出，调用失败按原因分类记成 gap，在时间线上单独可见——「为什么这步没有结论」始终可查，不会静默丢失。条目攒够一批，最旧的交给模型蒸馏成里程碑、原文移入归档，其中走过的死路全量保留零丢失，未完成目标跨折叠带下去。

新颖性判定：中文归一化后先做词法比对，再经模型 schema 自检确认；纯字面重复只记账不升级，只有语义重复才推进停滞级别。真人发来新消息归零所有状态，插件自己注入的消息不算。

上下文注入：下一步前把最近几条未完成目标（置顶）、里程碑、最近有推进意义的结论和几条死胡同注入上下文，更早的只报数量；预算紧张时逐级压缩，最后才降级成一行要点，不整块跳过。水位落后时明确标注，不拿陈旧条目冒充新结论。

三级停滞响应与静默中断：重复累积到不同级别，分别注入警示、请求上层拒读某类工具、请求硬终止本步并写交接账本。回合被步级上限、输出长度上限或运行时错误打断、且没形成面向用户的结论时，能识别出来并按设置决定是否在原窗口续跑；动作有四档，默认只检测并告警、不发任何消息，另外有冷却、每会话次数预算、进展校验、错误码排除等安全闸，真人接管永远优先。

右侧栏「语义监视」把以上痕迹合并成一条纵向时间线：账本条目、干预受理结果、折叠产出、总结跳过的原因、每步观察都按时间倒序列在一起，可展开看细节。宿主侧另有两个只读路由供面板取数。

## 安装

```sh
dsh plugin --profile <你的profile> add github:JiewiW/dsh-derive-watcher#v0.4.1
```

零第三方运行时依赖。账本默认落在 `~/.dsh/storages/semantic-watcher/`（设置项 `storagePath` 可改）。

## 设置

设置页按用途分七组（总开关 / 生成小结 / 塞回上下文 / 判断新旧内容 / 发现卡死 / 文件存放 / 静默中断），运行时经 `GET/POST /plugins/derive-watcher/settings` 读写，GET 返回完整 schema。每项在页面里有说明，键名与默认值以设置页和源码为准。

账本事件与载荷样例见 [docs/events.md](docs/events.md)。

## 怎么验收

```sh
npm test            # node --test --test-concurrency=1 "test/*.test.js"
npm run test:p225   # P2-25 事务四线回归
```

测试串行执行：timeline / assemble 两组用例都会写全局 settings.json，并行会互相踩踏。覆盖账本转写与长度守恒、词法比对边界、畸形 JSON 重试、折叠链完整性（死路零丢失）、注入预算与句界裁剪、停滞全部口径、干预受理埋点、时间线归并排序与降级、设置联动，以及上层治理不可用时的降级。

[replay/README.md](replay/README.md)：用真实事故会话加合成样例驱动，mock-LLM 离线确定性运行（不调真实模型、不写真实账本根），核验账本完整性、新颖性判定与三级停滞触发。
